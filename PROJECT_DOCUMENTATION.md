## Abstract

This project implements an end-to-end pipeline for two computer vision tasks — object detection and semantic segmentation — on the MNISTDD-RGB dataset. Synthetic scenes are generated by placing exactly two MNIST handwritten digits on randomly coloured noisy 128×128 RGB canvases, automatically producing ground-truth bounding boxes and pixel-level masks. YOLOv8 Small is fine-tuned on 100,000 training scenes for digit detection, achieving 97.92% detection accuracy and 94.39% F1 score. A custom 4-level U-Net is trained from scratch for pixel-level semantic segmentation, achieving 96.04% mean IoU and 99.96% pixel accuracy across 10,000 test scenes. Both models are trained, evaluated, and visualised in a single Jupyter notebook using Kaggle with dual T4 GPUs.

## 1. Introduction

### 1.1 Background

Computer vision enables machines to interpret visual data. Two of its most fundamental tasks are object detection — locating and classifying objects in an image using bounding boxes — and semantic segmentation — assigning a class label to every individual pixel. Together these tasks allow a system to answer both "what is where" and "which exact pixels belong to which object."

### 1.2 Problem Statement

Raw MNIST contains single isolated handwritten digits with no spatial complexity. Real-world digit recognition problems — such as reading postal codes, form numbers, or meter readings — require handling multiple digits simultaneously in the same image, with varying positions, sizes, and backgrounds. This project addresses that gap by constructing a synthetic multi-digit dataset and training two specialised models to detect and segment digits under these conditions.

### 1.3 Objectives

- Generate a synthetic MNISTDD-RGB dataset from raw MNIST with automatic ground-truth annotations
- Train YOLOv8 Small to detect and localise each digit with bounding boxes
- Train a 4-level U-Net to classify every pixel by its digit class
- Evaluate both models with Precision, Recall, F1, mean IoU, and Pixel Accuracy
- Demonstrate generalisation on held-out data not seen during training

### 1.4 Scope

The project generates 120,000 synthetic scenes from MNIST, trains two deep learning models on Kaggle GPU hardware, and produces a complete set of evaluation metrics and visualisations. The entire pipeline runs from a single Jupyter notebook.

## 2. Literature Review

### 2.1 Object Detection

Object detection has evolved from manual feature engineering to deep learning. Early approaches used handcrafted features to scan images at multiple scales, which was slow and limited. Deep convolutional networks improved accuracy significantly by learning features directly from data. Two-stage detectors propose candidate regions then classify them, achieving high accuracy at the cost of speed. Single-stage detectors predict boxes and classes in one pass, making them fast enough for real-time applications.

YOLOv8 is a modern single-stage anchor-free detector. Unlike grid-based predecessors that require predefined anchor shapes, YOLOv8 predicts bounding box coordinates as offsets from grid cell centres. This makes it more flexible for objects of varied sizes and removes the need for manual anchor tuning. It achieves state-of-the-art speed and accuracy and is well suited for small object detection tasks like digit localisation.

### 2.2 Semantic Segmentation

Semantic segmentation requires a class prediction for every pixel rather than just an image-level label. Fully convolutional networks established that classification backbones could be adapted for dense prediction by replacing fully connected layers with convolutions, preserving spatial information.

U-Net is a fully convolutional encoder-decoder architecture originally developed for medical image segmentation. Its defining feature is skip connections that directly concatenate encoder feature maps into the corresponding decoder level. This allows the decoder to combine deep semantic understanding from the bottleneck with fine-grained spatial detail from the encoder, producing precise object boundaries. U-Net has become the standard architecture for tasks requiring exact pixel-level boundaries.

### 2.3 MNISTDD-RGB Dataset

The MNIST Double Digits RGB dataset extends MNIST by placing two digits per scene on coloured backgrounds. Prior work on this dataset using a basic U-Net for both detection and segmentation achieved approximately 82% detection IOU and 75% segmentation accuracy. This project uses task-specific architectures — YOLOv8 for detection and U-Net for segmentation — achieving substantially higher results: 94.39% F1 detection and 96.04% mIoU segmentation.

## 4. Methodology and Design

### 4.1 Dataset Design

The MNISTDD-RGB dataset is generated synthetically from raw MNIST using the following process for each scene:

1. Create a 128×128 blank canvas with a random dark coloured background
2. Add Gaussian noise across the entire canvas
3. Sample two random MNIST digit images
4. Apply random scale (80–120%) and rotation (±15°) to each digit — training scenes only
5. Place each digit at a random position with a random bright colour applied to its strokes
6. Record the bounding box for each digit in YOLO format (normalised centre x, y, width, height)
7. Record the pixel-level mask where each pixel value indicates its digit class (0=background, 1–10=digit)
8. Save as RGB PNG image, YOLO label text file, and mask PNG

| Split | Scenes | Source | Augmentation |
|---|---|---|---|
| Train | 100,000 | MNIST train (60,000 digits) | Scale + rotation |
| Validation | 10,000 | MNIST train (60,000 digits) | None |
| Test | 10,000 | MNIST test (10,000 digits) | None |

The test split uses entirely separate MNIST digit images (the official test set) ensuring clean separation from training data.

### 4.2 Object Detection — YOLOv8 Small

YOLOv8 Small is a pretrained anchor-free single-stage detector fine-tuned for 10 digit classes.

**Architecture:**
```
Input: 128×128 RGB image
    ↓
CSPDarknet Backbone
    Extracts feature maps at multiple spatial scales
    ↓
PAN-FPN Neck
    Combines features from different backbone depths
    ↓
Three Detection Heads (stride 8, 16, 32)
    Each predicts: box coordinates + class probabilities
    ↓
Output: list of (x1, y1, x2, y2, digit_class, confidence)
```

| Property | Value |
|---|---|
| Parameters | 11.2 million |
| Pretrained on | COCO (80 classes) |
| Fine-tuned for | 10 digit classes |
| Input size | 128×128 |

**Training settings:**

| Parameter | Value |
|---|---|
| Epochs | 50 (max), patience=10 |
| Batch size | 256 |
| Optimizer | AdamW (auto lr=0.000714) |
| LR schedule | Cosine decay, 5-epoch warmup |
| Mixed precision | fp16 |
| Image caching | Full dataset in RAM |
| Multi-GPU | DDP across 2 T4s |

### 4.3 Semantic Segmentation — U-Net

A 4-level U-Net trained from scratch for 11-class pixel prediction (background + 10 digit classes).

**Architecture:**
```
Input: [B, 3, 128, 128]
    ↓
Encoder:
  Level 1: DoubleConv(3→32)   → [B, 32, 128, 128]
  Level 2: DoubleConv(32→64)  → [B, 64, 64, 64]
  Level 3: DoubleConv(64→128) → [B, 128, 32, 32]
  Level 4: DoubleConv(128→256)→ [B, 256, 16, 16]
    ↓
Bottleneck: DoubleConv(256→512) → [B, 512, 8, 8]
    ↓
Decoder (with skip connections from encoder):
  Level 4: Upsample + concat + DoubleConv → [B, 256, 16, 16]
  Level 3: Upsample + concat + DoubleConv → [B, 128, 32, 32]
  Level 2: Upsample + concat + DoubleConv → [B, 64, 64, 64]
  Level 1: Upsample + concat + DoubleConv → [B, 32, 128, 128]
    ↓
Output: Conv1×1(32→11) → [B, 11, 128, 128] (logits per pixel)
        Argmax → [B, 128, 128] (predicted class per pixel)
```

DoubleConv = Conv2d → BatchNorm → ReLU → Conv2d → BatchNorm → ReLU

Skip connections concatenate the encoder feature map at each level with the upsampled decoder output at the same spatial resolution, giving the decoder access to high-resolution spatial detail.

**Training settings:**

| Parameter | Value |
|---|---|
| Epochs | 20 (max), patience=5 |
| Batch size | 512 |
| Optimizer | AdamW (lr=1e-3, wd=1e-4) |
| Scheduler | ReduceLROnPlateau |
| Loss | CrossEntropyLoss |
| Mixed precision | AMP fp16 |
| Multi-GPU | DataParallel across 2 T4s |

## 5. Implementation Details

### 5.1 Notebook Structure

The implementation is contained in a single Jupyter notebook with 12 clearly labelled sections:

| Section | Purpose |
|---|---|
| 0 — Dependencies | Auto-installs all required packages |
| 1 — Configuration | All hyperparameters, paths, dynamic batch sizing from VRAM |
| 2 — Data Generation | Downloads MNIST, generates all synthetic scenes |
| 3 — Dataset Visualisation | Displays sample scenes with ground truth annotations |
| 4 — YOLO Training | Fine-tunes YOLOv8 Small, plots training curves |
| 5 — U-Net Training | Trains U-Net from scratch with early stopping |
| 6 — Segmentation Evaluation | Computes mIoU and pixel accuracy per class |
| 7 — Visualisations | Detection and segmentation result comparisons |
| 8 — Generalisation Test | Both models on held-out MNIST test images |
| 9 — Final Report | Saves complete metrics report to disk |
| 10 — Display Outputs | Embeds all output images inline in the notebook |
| 11 — Export | Packages outputs for download |

### 5.2 Key Technical Decisions

**Dynamic batch sizing:** Batch size is automatically determined from available VRAM at runtime, making the notebook hardware-agnostic. On T4 x2 (29 GB total) YOLO uses batch 256 and U-Net uses batch 512.

**RAM dataset loading:** The entire segmentation dataset (120,000 scenes) is pre-loaded into RAM as uint8 numpy arrays (approximately 3.2 GB) before training. This eliminates PNG decompression overhead during training, which was the primary cause of GPU starvation at 10–40% utilisation. After this change GPU utilisation reached 86–90%.

**Mixed precision training:** Both models use 16-bit floating point (fp16) during forward and backward passes via PyTorch AMP, giving approximately 2× speedup on T4 Tensor Cores.

**Multi-GPU:** YOLO uses Distributed Data Parallel (DDP) natively across both T4 GPUs. U-Net uses DataParallel with correct checkpoint unwrapping (.module) to handle the DataParallel wrapper during save and load.

**Early stopping:** YOLO stops if mAP does not improve for 10 consecutive epochs. U-Net stops if validation loss does not improve for 5 consecutive epochs, reloading the best checkpoint automatically.

## 8. Conclusion and Future Scope

### 8.1 Conclusion

This project demonstrates a complete object detection and semantic segmentation pipeline on the MNISTDD-RGB dataset. The key findings are:

- YOLOv8 Small achieves 94.39% F1 and 97.92% detection accuracy on 10,000 test scenes
- U-Net achieves 96.04% mean IoU and 99.96% pixel accuracy on the same test scenes
- Both results significantly exceed the prior baseline (82% detection IoU, 75% segmentation accuracy)
- Task-specific architectures — a dedicated detector for bounding boxes and a dedicated segmentor for pixel masks — outperform using a single model for both tasks
- Increasing training data from 60,000 to 100,000 scenes and upgrading from YOLOv8 nano to small improved detection F1 from 92.87% to 94.39%

The pipeline is implemented cleanly, runs end-to-end from a single notebook, and produces reproducible results on standard cloud hardware.

### 8.2 Future Scope

- **RT-DETR detector:** Replace YOLOv8 with a transformer-based detector that uses attention to attend to both objects in a scene simultaneously, potentially improving accuracy on overlapping digit cases
- **Real dataset:** Apply the same pipeline to the Street View House Numbers (SVHN) dataset — real photographs of door numbers — as a direct real-world extension of this work
- **Instance segmentation:** Replace semantic segmentation with Mask R-CNN to produce separate masks for each individual digit instance rather than class-level masks
- **Deployment:** Export both models to ONNX format and deploy as a real-time digit detection API
